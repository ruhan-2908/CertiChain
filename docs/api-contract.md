# CertiChain — API Contract

Base URL (local dev): `http://localhost:8080`

All request/response bodies are JSON. Protected routes need header:
`Authorization: Bearer <token>`

Status codes follow normal REST conventions (200/201 success, 400 validation
error, 401 unauthorized, 403 forbidden, 404 not found, 409 conflict).

---

## Auth — already built, live now

### `POST /api/auth/register`
Public.
```json
// Request
{
  "fullName": "Jane Student",
  "email": "jane@college.edu",
  "password": "StudentPass123",
  "role": "STUDENT"   // or "ADMIN"
}
```
```json
// Response 201
{
  "token": "...",
  "tokenType": "Bearer",
  "userId": 2,
  "fullName": "Jane Student",
  "email": "jane@college.edu",
  "role": "STUDENT"
}
```

### `POST /api/auth/login`
Public.
```json
// Request
{ "email": "jane@college.edu", "password": "StudentPass123" }
```
Response: same shape as register.

### `GET /api/auth/me`
Protected (any logged-in user).
```json
// Response 200
{ "id": 2, "fullName": "Jane Student", "email": "jane@college.edu", "role": "STUDENT" }
```

## Certificates — to be built by Backend Person A (upload-based)

Certificates are issued from an **uploaded PDF**, never generated by the
platform. The institution's existing document is the certificate; CertiChain
fingerprints and safely stores it.

### `POST /api/certificates`
Protected, `ADMIN` only. **`multipart/form-data`**, not JSON.

Form fields:
- `studentId` (number) — this is the `studentProfileId` from `/api/students`, not the userId
- `courseName` (text)
- `issueDate` (date, `YYYY-MM-DD`)
- `file` (the actual certificate PDF)

```json
// Response 201
{
  "id": 1,
  "certificateId": "CERT-2026-000123",
  "studentId": 1,
  "studentName": "Jane Student",
  "rollNumber": "CS2023-042",
  "courseName": "Semester 3",
  "issueDate": "2026-09-24",
  "documentUrl": "/files/CERT-2026-000123.pdf",
  "documentHash": "a1b2c3...",
  "blockchainTxHash": "PENDING_BLOCKCHAIN_INTEGRATION",
  "blockchainNetwork": "not-yet-integrated",
  "contractAddress": "not-yet-integrated",
  "status": "ACTIVE",
  "supersedesCertificateId": null,
  "supersededByCertificateId": null
}
```

### `GET /api/certificates` — Protected, `ADMIN` only. List all certificates.

### `GET /api/certificates/{certificateId}` — Protected, any logged-in user. Metadata only, not the file.

### `GET /api/certificates/{certificateId}/file` — Protected. `ADMIN`, or the `STUDENT` who owns this certificate. Streams the raw PDF (`Content-Type: application/pdf`). Not public — for the public check, see the Verification section below.

### `GET /api/certificates/my` — Protected, `STUDENT`. Their own certificates. **Read-only** — students cannot create, replace, or delete certificates anywhere in this API.

### `PUT /api/certificates/{certificateId}` — Protected, `ADMIN` only. `multipart/form-data`, same fields as create. "Replaces" a certificate by revoking the old one and issuing a brand new one linked to it (the blockchain record of the old certificate is never edited or erased — only marked revoked). Returns 201 + the new certificate's data.

### `DELETE /api/certificates/{certificateId}` — Protected, `ADMIN` only. Removes CertiChain's own record and file. Note: this cannot and does not remove anything already registered on the blockchain — nothing can, by design. Use `revoke`, not `delete`, to invalidate a certificate that may already be in circulation.

### `PATCH /api/certificates/{certificateId}/revoke` — Protected, `ADMIN` only. Unchanged.
```json
// Response 200
{ "certificateId": "CERT-2026-000123", "status": "REVOKED" }
```

## Verification — to be built by Backend Person B, public (no login)

There is exactly one way to verify a certificate: **upload the file**. The
backend hashes it and checks whether a matching hash is on record. No
Certificate ID entry, no QR scanning — just upload and check.

### `POST /api/verify/upload`
Public, `multipart/form-data`, field: `file` (the PDF to check).

```json
// Response 200 — match found, not revoked
{
  "result": "AUTHENTIC",
  "certificateId": "CERT-2026-000123",
  "studentName": "Jane Student",
  "courseName": "Semester 3",
  "issueDate": "2026-09-24"
}
```
```json
// Response 200 — match found, but revoked
{
  "result": "REVOKED",
  "certificateId": "CERT-2026-000123",
  "studentName": "Jane Student",
  "courseName": "Semester 3",
  "issueDate": "2026-09-24"
}
```
```json
// Response 200 — no matching hash on record at all
{
  "result": "NOT_FOUND"
}
```

Implementation notes for whoever builds this:
- Reuse the existing `HashingService.sha256Hex(MultipartFile file)` from
  the Certificate module — don't reimplement hashing here.
- Add `Optional<Certificate> findByDocumentHash(String documentHash)` to
  `CertificateRepository`, and mark the `documentHash` column
  `@Column(unique = true)` on the `Certificate` entity (two different
  certificates should never produce the same SHA-256 hash — if they
  somehow do, something is wrong upstream).
- Log every check to `verification_logs` (certificate_id if matched,
  method = `FILE_UPLOAD`, result, timestamp) regardless of outcome when that
  table/entity exists; otherwise leave a `// TODO:` and add it later.

## BlockchainService — Java interface, not an HTTP API

This is internal to the backend (used by Backend Person A + B), built by
Blockchain Person B. Documented here so everyone knows the shape:

```java
public interface BlockchainService {
    String registerCertificateHash(String certificateId, String hash); // returns tx hash
    CertificateRecord getCertificateRecord(String certificateId);       // read-only
    void revokeCertificate(String certificateId);
}

record CertificateRecord(
    String hash,
    String issuerAddress,
    Instant issueTimestamp,
    boolean revoked,
    boolean found
) {}
```

## Database structure (reference)

```
users
  id, full_name, email, password, role, enabled, created_at

students
  id, user_id (FK -> users), <any student-specific fields>

certificates
  id, certificate_id (unique, e.g. CERT-2026-000123), student_id (FK),
  course_name, issue_date, document_url, document_hash,
  blockchain_tx_hash, blockchain_network, contract_address, status

verification_logs
  id, certificate_id, method (FILE_UPLOAD), result,
  verified_at, ip_address (optional)
```
